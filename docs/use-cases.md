# Юзкейси системи TutorFlow

## Домен

**TutorFlow** — портал для репетиторів, який допомагає:

- вести базу учнів (`Student`);
- планувати навчальні заняття (`Session`);
- відстежувати робочий графік та статистику.

## Актори

- **Гість** — неавторизований користувач. Може лише реєструватись та входити.
- **Репетитор / Tutor** — авторизований користувач. Працює зі своїми учнями та заняттями.

У baseline-реалізації роль адміністратора не виділяється. Користувачі рівноправні і працюють лише зі своїми даними.

## UC-1. Реєстрація репетитора

- **Актор:** Гість.
- **Передумови:** немає.
- **Основний сценарій:**
  1. Гість надсилає `POST /api/auth/register` з `email`, `password`, `fullName`.
  2. Система валідує email і мінімальну довжину пароля.
  3. Система перевіряє, що користувач з таким email ще не існує.
  4. Пароль хешується через bcrypt.
  5. Користувач зберігається.
  6. Система повертає `201 Created` із даними користувача без пароля.
- **Альтернативи / помилки:**
  - Невалідний email або короткий пароль → `400 Bad Request`.
  - Email уже зайнятий → `409 Conflict`.

## UC-2. Вхід у систему

- **Актор:** Гість.
- **Передумови:** існує користувач із вказаним email.
- **Основний сценарій:**
  1. Гість надсилає `POST /api/auth/login` з `email` та `password`.
  2. Система знаходить користувача за email.
  3. Система перевіряє збіг пароля з хешем.
  4. Система видає JWT-токен.
  5. Повертається `200 OK`.
- **Альтернативи / помилки:**
  - Відсутні або невалідні поля → `400 Bad Request`.
  - Користувача немає або пароль невірний → `401 Unauthorized`.

## UC-3. Перегляд профілю

- **Актор:** Репетитор.
- **Передумови:** користувач має дійсний JWT.
- **Основний сценарій:**
  1. Репетитор надсилає `GET /api/auth/me` з заголовком `Authorization: Bearer <token>`.
  2. Система перевіряє токен.
  3. Система повертає дані поточного репетитора.
- **Альтернативи / помилки:**
  - Немає токена або токен неправильний → `401 Unauthorized`.

## UC-4. Додати учня

- **Актор:** Репетитор.
- **Передумови:** користувач авторизований.
- **Основний сценарій:**
  1. Репетитор надсилає `POST /api/students` з `fullName`, `subject`, `email`.
  2. Система перевіряє інваріанти:
     - `fullName` має містити мінімум 2 символи;
     - `subject` не може бути порожнім;
     - `email` має бути валідним, якщо переданий.
  3. Учень створюється з `tutorId = id поточного користувача`.
  4. Учню задається `status = "active"` і `balance = 0`.
  5. Система повертає `201 Created`.
- **Альтернативи / помилки:**
  - Невалідні дані → `400 Bad Request`.
  - Немає авторизації → `401 Unauthorized`.

  3. Повертається `200 OK`.
- **Альтернативи / помилки:**
  - Немає авторизації → `401 Unauthorized`.

## UC-6. Отримати учня за id

  3. Система повертає учня.

## UC-7. Оновити дані учня

- **Актор:** Репетитор.
- **Передумови:** користувач авторизований, учень існує і належить цьому репетитору.
- **Основний сценарій:**
  1. Репетитор надсилає `PATCH /api/students/:id` з полями, які потрібно змінити.
  2. Система перевіряє, що учень належить поточному користувачу.
  3. Система перевіряє інваріанти для переданих полів.
  4. Дані учня оновлюються.
  5. Система повертає `200 OK` і оновленого учня.
- **Альтернативи / помилки:**
  - Невалідні дані → `400 Bad Request`.
  - Немає авторизації → `401 Unauthorized`.
  - Учня немає або він належить іншому репетитору → `404 Not Found`.

## UC-8. Видалити учня

- **Актор:** Репетитор.
- **Передумови:** користувач авторизований, учень існує і належить цьому репетитору.
- **Основний сценарій:**
  1. Репетитор надсилає `DELETE /api/students/:id`.
  2. Система перевіряє, чи немає в учня майбутніх запланованих занять.
  3. Якщо майбутніх занять немає, учень видаляється.
  4. Система повертає `204 No Content`.
- **Альтернативи / помилки:**
  - Учня немає або він належить іншому репетитору → `404 Not Found`.
  - В учня є майбутні заняття → `409 Conflict`.
  - Немає авторизації → `401 Unauthorized`.

## UC-9. Запланувати заняття

- **Актор:** Репетитор.
- **Передумови:** користувач авторизований, існує учень, який належить цьому репетитору.
- **Основний сценарій:**
  1. Репетитор надсилає `POST /api/sessions` з `studentId`, `startsAt`, `endsAt`, `topic`.
  2. Система перевіряє, що учень існує і належить поточному репетитору.
  3. Система перевіряє інваріанти:
     - `startsAt` та `endsAt` — валідні ISO-дати;
     - `startsAt < endsAt`;
     - `startsAt` у майбутньому;
     - заняття не перетинається з іншим заняттям цього репетитора.
  4. Заняття створюється зі статусом `"scheduled"`.
  5. Система повертає `201 Created`.
- **Альтернативи / помилки:**
  - Невалідні дати або поля → `400 Bad Request`.
  - Перетин зі вже наявним заняттям → `409 Conflict`.
  - Учня немає або він належить іншому репетитору → `404 Not Found`.
  - Немає авторизації → `401 Unauthorized`.

## UC-10. Список занять

  4. Повертається `200 OK`.
- **Альтернативи / помилки:**
  - Немає авторизації → `401 Unauthorized`.

## UC-12. Оновити заняття

- **Актор:** Репетитор.
- **Передумови:** користувач авторизований, заняття існує і належить цьому репетитору.
- **Основний сценарій:**
  1. Репетитор надсилає `PATCH /api/sessions/:id`.
  2. Система перевіряє, що заняття належить поточному користувачу.
  3. Якщо змінюється `studentId`, система перевіряє нового учня.
  4. Система перевіряє інваріанти часу.
  5. Система перевіряє, що оновлений слот не перетинається з іншими заняттями.
  6. Дані заняття оновлюються.
  7. Повертається `200 OK`.
- **Альтернативи / помилки:**
  - Невалідні дані → `400 Bad Request`.
  - Немає авторизації → `401 Unauthorized`.
  - Заняття або учня немає → `404 Not Found`.
  - Перетин із заняттям → `409 Conflict`.

## UC-13. Скасувати або завершити заняття

- **Актор:** Репетитор.
- **Передумови:** користувач авторизований, заняття існує і належить цьому репетитору.
- **Основний сценарій:**
  1. Репетитор надсилає `PATCH /api/sessions/:id/status`.
  2. У тілі запиту передається `status = "cancelled"` або `status = "completed"`.
  3. Система перевіряє допустимість переходу статусу.
  4. Статус заняття оновлюється.
  5. Повертається `200 OK`.
- **Альтернативи / помилки:**
  - Передано неправильний статус → `400 Bad Request`.
  - Не можна завершити заняття, яке ще не почалося → `409 Conflict`.
  - Не можна скасувати вже завершене заняття → `409 Conflict`.
  - Заняття немає або воно належить іншому репетитору → `404 Not Found`.
  - Немає авторизації → `401 Unauthorized`.

## Зведена таблиця інваріантів

| Сутність | Інваріант |
| -------- | --------- |
| User | `email` — валідний формат; `password` — мінімум 6 символів; email унікальний. |
| Student | `fullName` ≥ 2 символів; `subject` непорожній; `email` валідний, якщо переданий. |
| Session | `startsAt < endsAt`; `startsAt > now`; немає перетину з іншими заняттями того ж репетитора. |
| Session | `studentId` належить поточному репетитору; перехід статусів узгоджений із бізнес-правилами. |
